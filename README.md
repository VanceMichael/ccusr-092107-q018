# 运河古建联防监测

保存运河古建、病害观察、保护干预和公众利用资料。代码模块只负责读取和校验这些资料，后续业务服务可以沿用其中的领域标识与版本约定。

## 领域资料

`contracts/context.schema.json` 约定资料格式，`fixtures/context.json` 提供不含真实个人信息的示例（编号、机构名均为虚构）。资料包含：

- **遗产点 `heritage_points`**：钞关、会馆、水工遗址、古镇民居各至少一处，带沿运河桩号（判上下游）和适用阈值档案。
- **差异化阈值 `threshold_profiles`**：四类遗产点各有一套 `正常 / 预警 / 处置` 阈值，类型与档案一一绑定，不能混用。例如 2.1mm 裂缝在会馆已须处置、在钞关和古镇民居仅预警、在水工遗址仍属正常。
- **观察样例 `observation_samples`**：监测读数，指标与单位必须落在该点所属类型的阈值内。
- **档案 `archives`**：按建筑、构件、碑刻、材质、周边环境五类建档；每份档案由版本组成，版本沿 **监测 → 巡查证据 → 病害判断 → 干预方案 → 施工 → 开放条件** 六阶段逐版衔接，只许追加、不许回退。
- **干预 `interventions`**：只能依据已批准的病害判断版本；须评估对上游、下游遗产点水环境的影响（按桩号核对方向）和对各点开放安排的影响；专家争用、预算争用、上下游影响、三维模型换版、居民隐私、游客量变化六项必须逐项进入决策。
- **三维模型 `models_3d`**：换版时旧版转“历史”，每个遗产点至多一个“现行”模型，干预决策只能引用现行模型。
- **公众导览 `public_guides`**：已发布导览引用的解释必须来自对应档案的最新有效批准版本；草稿可暂挂待批版本。

### 两条硬规则

1. **原状资料永不覆盖**：`is_original_state_record` 的版本只能是“已批准”、不能声明 supersede、不能作废；后续版本只追加。
2. **紧急加固先处置后补审**：紧急版本状态为“先处置待补审”，必须在后续版本补审追认（双向指向）；补审尚在办理时允许 `ratified_by_version` 为 null。

居民隐私通过档案版本上的 `record_privacy` 记录脱敏与访问限制（入户影像不进公众导览）。

## 查询助手

`src/context.py` 在加载校验之外提供：

- `classify_reading(...)`：按遗产点所属类型的阈值判定 正常/预警/处置；
- `latest_approved_version(...)`：取档案最新批准版本（导览引用依据）；
- `current_model(...)`：取遗产点现行三维模型；
- `parse_ref(...)` / `get_version(...)`：解析与读取 `档案#版本号` 引用。

## 本地校验

```
python -m unittest discover -s tests
```

26 项测试覆盖正常路径与各类违规反例：类型与阈值错配、原状资料被作废、阶段回退、紧急处置缺补审、引用未批准/过时版本、上下游方向错误、引用历史模型决策、导览引用旧版解释等。
