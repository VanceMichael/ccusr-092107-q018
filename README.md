# 运河古建联防监测

保存运河古建、病害观察、保护干预和公众利用资料。

## 领域资料

`contracts/context.schema.json` 约定基础资料格式，`fixtures/context.json` 提供不含真实个人信息的示例。代码模块只负责读取和校验这些资料，后续业务服务可以沿用其中的领域标识与版本约定。

当前资料记录了以下业务事实：

- 运河遗产点多线长且结构材质差异明显
- 保护正从单点守护转向统一监测和线性联通
- 数字建模、导览和水上游线被用于活化利用
- 钞关、会馆、水工遗址与仍有人生活的古镇民居病害阈值各异，不可共用一套
- 单点修缮可能改变整条运河文化线路的水环境与开放安排
- 档案按建筑、构件、碑刻、材质、周边环境五个维度保存
- 监测、巡查证据、病害判断、干预方案、施工与开放条件逐版衔接
- 紧急加固允许先处置后补审，原状资料永远不能被覆盖
- 专家与预算争用、上下游影响、三维模型换版、居民隐私与游客量变化均纳入决策
- 公众导览引用的解释必须来自最新批准版本

## 资料结构

- `threshold_profiles`：按遗产类型分别定义病害预警与危急阈值，观察样例只能套用本类型的阈值
- `heritage_sites`：遗产点及其五维档案，原状首版标记 `immutable`，永不覆盖
- `observations`：观察样例，锚定遗产点与对应类型的阈值
- `evidence_chains`：监测到施工与开放条件的五阶段证据链，换版记录注明被接替版本，相邻阶段逐版衔接
- `interventions`：干预方案，紧急加固可先处置后补审；每案必须锚定原状资料并说明对线路水环境与开放安排的影响
- `decisions`：决策记录，专家争用、预算争用、上下游影响、三维模型换版、居民隐私、游客量变化六项因素缺一不可
- `interpretations` 与 `guide_citations`：公众导览只能引用最新批准版本的解释

## 本地校验

运行 `python -m unittest discover -s tests` 可确认示例资料能够读取，且领域标识、版本、事实列表完整，上述领域规则全部成立。示例中的名称与编号均为虚构值，不包含账号、凭据或真实主体信息。
